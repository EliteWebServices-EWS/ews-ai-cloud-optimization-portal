# EC2 Security & Governance Analysis

The EC2 security analyzer is a read-only, mocked-inventory integration point for later AWS discovery work. It does not call AWS or modify EC2 resources.

## API

- `POST /api/v1/analysis/ec2/security` (analyst or admin): submits `{ inventory, policy? }` and returns per-instance findings, security score, governance score, risk level, and remediations.
- `GET /api/v1/recommendations/ec2/security`: returns recommendations generated by the most recent process-local analysis. Run the POST endpoint first.

Each inventory item needs `instanceId` and `instanceType`. Optional security evidence includes `publicIpAddress`, security-group inbound rules, EBS encryption state, IAM profile ARN, metadata token mode, CloudWatch monitoring, and backup policy. Governance checks cover required tags, Name tag naming, approved instance families, backup indicator, and instance age.

## Defaults and integration boundary

Defaults require `Name`, `Environment`, and `Owner` tags; allow common T3/M5/M6i/C5/C6i/R5/R6i families; enforce lowercase hyphenated names; and set a 365-day lifecycle review threshold. Requesters can override tag, instance-family, and lifecycle policy fields in the POST body. The naming standard is fixed in code so untrusted requests cannot supply a potentially unsafe regular expression.

The recommendation cache is deliberately process-local while mocked inventory is in use. Engineer 1's inventory/discovery provider should replace the request inventory and persistence layer without changing analyzer semantics.
